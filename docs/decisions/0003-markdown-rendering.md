# 0003. Markdown Rendering and Sanitization

- **Status:** Accepted
- **Date:** 2026-10-18
- **Revisit:** Before exercise content can be authored by anyone outside this repository, which in the current plan means organizations (`codegym-nmf`)

## Context

Exercise bodies are authored as Markdown in `db/exercises/` and stored in `exercises.body_md` (decision 0002). The exercise page has to render them. Rails ships no Markdown renderer, so this is a dependency decision, and swapping renderers later changes the output of every exercise at once — which is what makes it worth recording.

Two constraints shape it:

**Trust changes over time.** `CLAUDE.md` is explicit that `body_md` is trusted content written by us *for now*, and that sanitization becomes mandatory once anyone else can author exercises. The content is trusted today; the code path will outlive that fact.

**The content is plain.** The twelve starter exercises use headings, paragraphs, fenced code blocks, lists, inline code, emphasis and the occasional link. Nothing exotic, and nothing that needs raw HTML.

## Decision

Render with **commonmarker** (2.10), the Ruby binding to comrak, configured as:

- `render: { unsafe: false }` — raw HTML in the source is omitted rather than passed through.
- `extension: { table: true, strikethrough: true, header_ids: nil }` — tables and strikethrough on; no autogenerated heading anchors, which otherwise add an empty link and an `aria-label` to every heading.
- `plugins: { syntax_highlighter: nil }` — off. It is on by default and inlines a fixed dark theme as `style` attributes on every token, which bloats the HTML, ignores the reader's colour scheme, and would be stripped by the sanitizer anyway. A fenced block renders as a plain `<pre lang="ruby"><code>`, so the language is still there when syntax highlighting is added deliberately.

Then pass the result through **`Rails::HTML5::SafeListSanitizer`** with an explicit allowlist of tags and three attributes (`href`, `title`, `lang`). No `img` and no `class`: exercises are text, and neither has a use yet.

Both layers, in `app/models/markdown.rb`. The sanitizer is redundant today, because commonmarker already drops raw HTML — that is the point. A guard installed while the content is trusted is one that cannot be forgotten later, under deadline, by someone who does not know it was missing.

Verified behavior rather than assumed: `<script>`, `<img onerror=…>` and `<iframe>` all render empty, a `javascript:` href is blanked, a `data:` URI image is stripped, and ordinary links, tables and fenced code survive.

## Alternatives considered

**Redcarpet.** The long-standing default and perfectly capable, with `filter_html` and `escape_html` options. Lost on spec compliance: it is built on Sundown and predates CommonMark, so its edge-case behavior around nested lists and fenced blocks is its own rather than specified. Exercise bodies are the product, and predictable rendering matters more than familiarity.

**Kramdown.** Pure Ruby, no native extension, which is genuinely attractive for portability and for an app that tracks Rails main and does not need more moving parts. Lost because GFM support needs a second gem, it is substantially slower, and the native-extension worry turned out to be moot: commonmarker ships precompiled gems and `Gemfile.lock` already resolved every platform CI and the Docker image use, with checksums.

**Rendering in the browser.** Ship `body_md` and render client-side. Rejected: it makes the page useless without JavaScript, moves a security boundary into the client, and the content is static and identical for every reader, so there is nothing to gain for the cost.

**Sanitizing only when untrusted content arrives.** Rejected for the reason above. It is the same amount of work, done later, by someone with less context, at the moment the risk becomes real.

## Consequences

**Good**

- CommonMark plus GFM, so rendering matches what the author saw in any standard preview.
- Two independent layers, either of which would stop injected markup on its own.
- `codegym-nmf` becomes a review of an existing allowlist rather than new work.
- The language survives on `<pre lang>`, so syntax highlighting is additive later.

**Bad**

- A native-extension dependency, which is one more thing that can fail to build on a platform with no precompiled gem. Mitigated, not eliminated, by the lockfile covering every platform in use.
- The allowlist will silently drop anything new an author tries, such as an image or a footnote, and the failure looks like missing content rather than an error. Anyone widening the Markdown surface has to widen the allowlist in the same commit.
- Rendering happens per request. Fine at twelve exercises; if the library grows or pages get slow, cache the rendered HTML rather than loosening either layer.
